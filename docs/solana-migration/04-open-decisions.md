# 04 — Відкриті рішення

Ці п'ять рішень міняють обсяг фази 2. Terra не має вирішувати їх сама — якщо на
момент старту фази 2 відповіді немає, брати варіант «за замовчуванням».

## D1. Результати: Merkle-корінь чи PDA на кожного учасника

| | Merkle (за замовчуванням) | PDA на учасника |
|--|--------------------------|-----------------|
| Сеттл | 1 транзакція на тур | ~N/20 транзакцій |
| Рента | тільки за тих, хто claim'ить | за всіх учасників |
| Leaderboard | JSON з бекенду + перевірка хеша | читається з ланцюга |
| Прозорість | корінь у ланцюгу, дані поруч | повністю в ланцюгу |

Рекомендація: **Merkle**. Очки вже рахує оракул, повна таблиця в ланцюгу не
додає довіри пропорційно до вартості.

## D2. Статистика гравців у ланцюгу

| Варіант | Вартість | Що дає |
|---------|----------|--------|
| Hash-commit (за замовчуванням) | ~1 tx на тур | JSON незмінний після публікації, перевіряється будь-ким |
| Чанковані акаунти | ~6–8 tx і рента на тур | статистика читається з ланцюга |
| Не публікувати | 0 | нічого |

Рекомендація: **hash-commit**. Це зберігає головну властивість — неможливість
тихо переписати статистику заднім числом.

## D3. Titles і guilds

Зараз це платні випадкові бонуси на MOVE, і в бойовому `calculate_results_v3`
вони **не впливають** на final points. На Solana нативного рандому немає:
потрібен Switchboard VRF або commit-reveal.

| Варіант | Наслідок |
|---------|----------|
| Drop (за замовчуванням) | мінус сторінка `titles`, мінус два поля доходу, мінус залежність від VRF |
| Порт зі Switchboard VRF | +інтеграція, +вартість запиту, +час |
| Порт з commit-reveal | без зовнішньої залежності, але 2 транзакції на роздачу |

Рекомендація: **drop у першому релізі**, повернути пізніше, якщо це реальне
джерело доходу. Це видно з даних Movement — варто звірити.

## D4. WC bracket

Чемпіонат світу завершився. Код bracket робочий і недорогий (92 байти на
прогноз), але зараз не використовується.

Рекомендація за замовчуванням: **перенести структуру, але не включати в перший
деплой** — інструкції пишуться у фазі 2 за прапорцем `feature = "bracket"`, UI
підключається пізніше під наступну подію.

## D5. Поповнення USDC

Stableyard був зав'язаний на Movement (chain id 10002). На Solana цей шлях
відпадає.

| Варіант | Плюси | Мінуси |
|---------|-------|--------|
| Тільки зовнішні гаманці (за замовчуванням) | нуль інтеграцій | втрачаємо не-crypto користувачів |
| On-ramp (MoonPay/Transak у Phantom) | фіат → USDC у гаманці | комісії, KYC |
| Privy embedded wallets на Solana | найкращий onboarding | велика інтеграція, окрема фаза |

Рекомендація: перший реліз — **зовнішні гаманці**, on-ramp як окрема задача
після того, як основний flow працює.

## D6. Чи лишати обидва ланцюги живими

Технічно так — скоринг уже off-chain, тож два ланцюги означають два деплої
однієї спеки й один спільний оракульний конвеєр. `chainClient.ts` із фази 1
навмисно спроєктований так, щоб мережа була деталлю реалізації, а не
припущенням у сторінках.

| Режим | Що це | Ціна |
|-------|-------|------|
| Read-only архів (за замовчуванням) | Movement лишається доступним для перегляду історії, нових турів немає | ~0 |
| Claims-only вікно | 60–90 днів на забір старих призів, потім read-only | RPC + невеликий supervision |
| Повний dual-chain | Тури йдуть паралельно на обох мережах | ~2× операцій, розділений призовий пул |

Головний аргумент проти повного dual-chain — не код, а **призовий пул**. Тур на
$1240 привабливий; два тури по $620 — гірший продукт на обох мережах. Плюс
подвійний сеттл щотижня, два treasury, два ключі оракула, два аудити, подвійна
підтримка. Для команди вашого розміру це відбирає ресурс саме тоді, коли треба
доводити продукт на новій мережі.

Рекомендація: **claims-only вікно → read-only архів**, а можливість повернути
Movement лишається в коді через абстракцію клієнта. Дизайн дволанцюговості
зберігаємо, експлуатацію — ні.

## Дрібніші рішення, які приймаються всередині фази 2

- `admin_reset_gameweek_registrations`: реалізувати як `close_entry(gw, owner)` з
  поверненням entry fee, доступний адміну лише у статусі OPEN/CLOSED.
- Дублікати гравців у складі — додати перевірку (у Move її немає).
- `reopen_gameweek` — заборонити, якщо вже був хоч один claim.
- Кількість адмінів — фіксований масив на 5; практично один Squads multisig.
